# Java Coach

Teaching repo for junior developers. Pick the obvious solution and copy the patterns already here.
User-facing docs: `docs/guide/` (rendered at /docs). Skills: `.claude/skills/`.

## Commands

- `pnpm dev`: web (Vite, :5173) and server (Express, :3001) together
- `pnpm dev:web` / `pnpm dev:server`: one side only
- `pnpm test` (all), `pnpm test -- src/domain` (a folder), `pnpm test:coverage`
- `pnpm lint`, `pnpm typecheck`, `pnpm format`
- `pnpm check`: lint + typecheck + test. Run before every commit.
- `pnpm dlx shadcn@latest add <name>`: add a shadcn/ui component
- `pnpm exec codex login` (once), `pnpm codex:try [cv.pdf]`: check the real Codex coach

## Where code goes

- `src/domain/`: pure TypeScript. Types, the `CoachService` interface, business rules
  (levels, gaps, path order, progress, CV file rules). No React, no fetch, no storage.
  ESLint enforces this.
- `src/infrastructure/`: code that does I/O: `MockCoachService`, `HttpCoachService`, `extractPdfText`.
- `src/app/`: composition root, providers, router, layout. The only place that picks implementations.
- `src/features/<feature>/`
  - `components/`: render and delegate. No business rules in JSX.
  - `hooks/`: glue between components and TanStack Query, Zustand or domain functions.
  - `model/`: feature-local types and Zustand stores.
  - `api/`: query keys and query/mutation functions.
  - Create only the subfolders a feature needs.
- `src/components/ui/`: generated by shadcn. Do not hand-edit.
- `src/test/`: render helpers, MSW server, fixtures. Tests sit next to the file they test (`x.test.ts`).
- `server/src/`: `http/` (Express routes), `application/` (use cases, no Express/SQLite/Codex
  imports), `infrastructure/` (SQLite repository, Codex engine). `server/src/main.ts` wires them.
- `docs/specs/<feature>.md`: acceptance criteria. `docs/api-contract.md`: HTTP contract.

## Naming

- Files are kebab-case (`learning-step-card.tsx`). Components are PascalCase. Hooks are `useX`.
- Use the domain vocabulary: CoachReport, SkillArea, SkillLevel, SkillRating, Gap, LearningStep.
  Do not invent synonyms (no "Skill", "Weakness", "Task").

## State

- TanStack Query: data that comes from the coach (`['coach-report']`, persisted to localStorage).
- Zustand: client UI state (learning progress, persisted with the `persist` middleware).
- `useState`: state used by one component only. No other state libraries.

## Feature workflow (test-first, in batches). Use the `feature-tdd` skill.

1. Write `docs/specs/<feature>.md` with numbered acceptance criteria.
2. Write the complete test suite from the spec: domain unit tests, hook tests, component tests.
3. Run it once and confirm every test fails for the right reason (missing code, not a typo).
4. Implement until the whole suite is green, then refactor with tests green.
5. `pnpm check`, then commit: `feat(<feature>): ...`.

- No tiny red/green loops. Never weaken or delete a test to make it pass. If a test is wrong,
  fix the spec first, then the test, and say so.
- Test behaviour: query by role/label/text, act with `userEvent`. Do not assert on hook
  internals, class names or store shape from component tests.
- `src/domain` must stay at 100% coverage (enforced by `pnpm test:coverage`).

## Hard do-nots

- No API keys, tokens or secrets in frontend code or in `VITE_*` variables.
- Features never import from `src/infrastructure`; they call `useServices()`.
- Never call real Codex or the network in tests: use fakes and MSW.
- Do not add abstractions with a single implementation and no reason to vary.
- Do not add new skills, agents or slash commands.
- Code snippets in `docs/guide/` must match the source. `src/features/docs/docs-snippets.test.ts`
  checks this.
